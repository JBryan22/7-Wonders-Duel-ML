## Notes

- **Command name:** `7wd-train start | pause | status | shortcuts` (Python entry point in `training/`, `uv run 7wd-train …`, or `training/.venv/Scripts/7wd-train.exe` / `.venv/bin/7wd-train`), not a `train` subcommand of the C# `7wd`. Reason: the loop rebuilds `engine/src/Cli` at every start, which can't overwrite a 7wd.dll that is running the command. Code: `sevenwd/control.py` (commands), `runstate.py` (status/lock/pause files, status line), `stopping.py` (stopping rule), `notify.py`; loop changes in `loop.py`.
- **Start** creates (`--run DIR --config FILE`) or continues the current Run (remembered in `runs/current.txt`, or `SEVENWD_CURRENT_RUN`). It checks the Run itself (refusals are shown), then launches `python -m sevenwd.loop` detached (Windows: hidden console + own process group + breakaway from an SSH job when allowed; Linux: new session), output in `<run>/loop.out`. `--generations N` is per start, like `sevenwd-loop`. One loop per Run via an OS file lock (`loop.lock`), so "is it running?" survives crashes.
- **Pause** writes `<run>/pause.request`. The loop checks it before every step; C# `selfplay`/`match` got `--stop-file F` (new `Agents/StopFile`, polls every 0.5 s) and stop as with Ctrl+C; training checks it after every step (`train(..., tick=)`), saves the checkpoint, and the plan keeps the partial loss sums so the Generation's losses still average over all its steps. Measured on the desktop: paused within ~1 s in Self-Play, training and a Match. Losses: Self-Play drops games in progress (seconds each), training nothing, a Match the seed pairs in progress (at 800 sims a pair can take ~1 min: the spec's granularity). If the loop doesn't stop within `--wait` (120 s), pause kills its process tree. Ctrl+C on a foreground `sevenwd-loop` also saves the training checkpoint.
- **Status** is one line from `<run>/status.json` (rewritten every step and every 15 s by a heartbeat): state (running / paused / stopped / done / refused, or "interrupted" when it says running but no loop holds the lock), reason, step and progress (games / steps / seed pairs), Generations done, latest Elo and Anchor score, best, desktop-hours of the cap. `pause` and `status` don't import PyTorch (~0.3 s).
- **Desktop-hours** = time with the loop running, carried across sessions in `status.json` (`active_seconds`), also in the new `generations.csv` column `hours`. The per-row `seconds` is still only the last session's part of a Generation.
- **Stopping rule** (new config section `stop:`, in `default.yaml`; null switches a rule off): `cap_hours` 300, `plateau_generations` 20, `science_min_share` 0.01 over `science_from`–`science_to` (6–10), `progress_by` 20. Anchor Elo is computed from the Anchor Match score (relative to the Anchor; error bar = half the 95% interval in Elo). Plateau: best Anchor Elo after g−20 ≤ the last one at/before g−20 + its error bar. No progress: by Gen 20, no Anchor Match above the first one by more than its error bar. Cap/plateau are checked between Generations and again at every start (the Run won't start while one holds; `start --ignore-stop` records the rule in `overrides.json` and goes on). Warm-start triggers fire only on their own Generation, so a start afterwards just continues. Ticket 26 may need to retune `plateau_generations`/`anchor_every` together.
- **Faults:** a Generation that raises is retried once after 30 s; a second failure stops the Run (`stop_kind: fault`, traceback in `loop.log`). A self-stop is recorded in `status.json`, `generations.csv` (`stop_reason` column; not for faults, which have no finished row), TensorBoard text `stop_reason`, plus a notification (Windows toast via PowerShell WinRT, `notify-send` on Linux; `SEVENWD_NOTIFY=0` disables; tests set it). Loop exit codes: 0 done, 1 refused/fault, 2 paused, 3 self-stopped.
- **Shortcuts:** `7wd-train shortcuts` made "Start training" and "Pause training" on this desktop (`OneDrive\Desktop`), pointing at `.venv\Scripts\7wd-train.exe start|pause --hold 20` (window stays 20 s). They act on the current Run, so the first Run must be created once with `--run/--config`.
- `pyproject.toml` now sets `[tool.uv] link-mode = "copy"`, so `UV_LINK_MODE=copy` is no longer needed on the OneDrive checkout. After pulling, `uv sync` installs the `7wd-train` script (if the known "failed to remove dist-info" error appears, `uv sync --reinstall-package sevenwd`).
