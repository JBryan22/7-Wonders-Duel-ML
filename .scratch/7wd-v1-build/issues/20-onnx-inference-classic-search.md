## Notes

- Code (`Agents/Neural/`): `NeuralNetwork` (ONNX Runtime session; `Load(path, device, cpuThreads)` does the handshake: `format=7wd-network`, `encoding_version` = `NetworkEncoding.Version`, input/output names and sizes, outcome classes; otherwise `FormatException` naming both versions), `InferenceBatcher` (one inference thread per model; greedy batching: takes everything queued, max 512, never waits to fill; `Batches`/`Positions` counters), `LoadedNetworks` (process-wide cache per file+write time+device+threads, so all Agents of a Match share one batcher), `ILeafEvaluator` with `NetworkEvaluator`, `UniformEvaluator` (logits 0, value 0) and `PlayoutEvaluator` (uniform policy, one random playout as value), `NeuralAgent` (+ `NeuralSettings`, `NeuralResult`, `NeuralMoveStat`), `NetworkBench`.
- Spec: `neural:<onnx>[,sims=800,c=1.25,noise=0,alpha=0.3,temp=0,device=cpu,threads=4,mode=classic]`, parts in any order; `neural:uniform` / `neural:playout` are the built-in references. `mode=gumbel` is refused until ticket 21 (which should add it and probably make it the default). Not rated in the Ladder.
- Search: same open-loop, chance-at-the-Reveal tree as `MctsAgent` (Determinizer world per simulation, `CopyFrom` reuse). A leaf is evaluated after any Reveal in front of it. Each evaluated node keeps the network's full logit vector (1,509 floats; ~4.8 MB per Agent at 800 sims) and priors are the softmax over the Moves legal in the current world, so Moves that only some Reveals make legal still get a prior. PUCT `Q + c·P·√N/(1+n)` with N = visits of the currently legal children; values −1..1 per edge from its mover's view; unvisited Q = parent's mean (FPU). Root noise is mixed into priors and written back as root logits. Temperature 0 = most visits (ties: value, then prior). Output: per-Move visits/share/prior (pre-noise)/value as win prob/StdErr, principal line (`LineStep`, ≥ 4 visits), root network value and outcome-class probabilities, `PolicyTarget` = root visit shares (classic training target).
- ONNX Runtime 1.31: `Microsoft.ML.OnnxRuntime.Gpu.Windows` on Windows, `Microsoft.ML.OnnxRuntime` (CPU) elsewhere, chosen by OS in `Agents.csproj` (avoids ~500 MB of Linux CUDA libraries the laptop can't use). The CUDA provider needs CUDA 13 + cuDNN 9: found automatically in `training/.venv/Lib/site-packages/torch/lib` (PyTorch cu130 wheel), or `SEVENWD_CUDA_LIBS`; no CUDA toolkit install needed. Builds copy ~215 MB of native DLLs into each Windows output folder (bin/ is in OneDrive).
- **Default device is the CPU** (`device=cuda` or `device=auto`, CUDA when it can load, opt in). `7wd netbench <onnx>` measured the 256×4 net (desktop, 16 threads; the GPU was busy with a game, so redo CUDA numbers in ticket 26): CPU batch 1 0.15 ms (4 threads), batch 16 0.34 ms, 64 1.2 ms, 1024 11–15 ms (~90k pos/s); CUDA batch 1 2.6 ms, 64 6.3 ms, 1024 9.6 ms (~107k pos/s). CUDA only wins at batch ≈ 1,000, so Self-Play (ticket 22) should run enough games in parallel for big batches before choosing CUDA.
- ORT CPU threads matter a lot when 16 game threads share the batcher (16 pairs, 200 sims vs random): threads=1 21.5 s, 2 9.9 s, 4 7.5 s, 8 6.7 s, ORT default 14.9 s, 16 82 s (spinning threads fight the game threads); disabling spinning was worse. Default 4. Mean batch in a 16-thread Match ≈ 9.
- Batch-invariance: on the CPU each position's outputs are bit-identical whatever else is in its batch (tested), so neural Matches are deterministic for fixed seeds regardless of thread count. CUDA numbers differ slightly from CPU (games diverge), so compare devices statistically.
- Measurements (200 pairs, base): `neural:<random gen-0 256×4>` (800 sims) vs random: 71.8 % (67.1–75.9), Elo +162 (search over random priors and values still beats Random); 355 ms per Move at 800 sims with 16 games in parallel (~27k positions/s, mean batch 7.3) — slow, ticket 22 needs bigger batches (more games than cores, or leaf batching inside a search). `neural:playout,sims=1000` vs `mcts:sims=1000,margin=0`: 45.0 % (40.2–49.9), Elo −35: PUCT with uniform priors and playout values plays close to plain MCTS (a bit weaker; c=1.25 was not tuned for playout values). Both ~44 ms per Move.
- Found in passing: the Anchor's margin term (0.02 × VP margin) can make it pass up an immediate military win for a bigger civilian margin in won positions; harmless for strength but worth knowing when reading its choices.
- Test fixtures: `engine/tests/Agents.Tests/Models/` (`tiny.onnx` 8×1 random + `tiny.expected.json` torch outputs, `zero.onnx` all-zero weights = uniform policy/value 0, `wrong-version.onnx` stamped v999; ~220 KB total), regenerated by `uv run python -m sevenwd.test_models` in `training/`. After an Encoding change, regenerate them too (the Python test checks the committed ones against the manifest).
