# Tabletop Simulator scripts

The read-only Lua snapshot script and the TTS-name → slug table for the Tabletop Simulator Adapter (spec A9, ADR 0004). Nothing here is ever added to the mod or the save.

- `snapshot.lua`: sent by the Advisor through TTS's External Editor API ("Execute Lua Code" on Global). It reports every game piece with its raw position and sends the Table Snapshot back as one JSON string with `sendExternalMessage`. It only reads, and it filters hidden information inside TTS: a card is named only face up or in the discard pile, decks only in the discard pile, Progress tokens never in a Great Library draw strip, nothing in a hand, and no GUIDs.
- `names.json`: the mod's object names → slugs. The mod's "Courthouse" is the Age III red card (`pretorium`) and its "Tribunal" is our `courthouse`.
- `places.json`: where things sit on the mod's table (pyramid grid for all three Ages, cities, Wonder columns, discard tile, token areas, track). `TableView` (engine/src/Advisor/Tts) turns a snapshot into places with it.
- `fixtures/ml-practice.snapshot.json`: the snapshot the script gives for the committed Age II save `docs/research/tts-mod/ml-practice.json` (generated by the tests in a fake table; rewrite with `UPDATE_TTS_FIXTURE=1 dotnet test`).
- `fixtures/pantheon-pieces.json`: the mod's Pantheon pieces, extracted from the Workshop file (every object of its Pantheon zone, with contents, image/back hashes, and what the Global script spawns for Pantheon: the board and its snap points, the Divinity boards). The tests check `names.json` and `places.json` against it.
- `fixtures/pantheon-age2.snapshot.json` and `pantheon-age2.log`: a recorded Pantheon Age II table (painted from a seeded game, read through the script) and the owner's log of that game.

**Pantheon** (Pantheon ticket 13, spec-pantheon P-A9): read only in Pantheon games, so a base table reads exactly as before. `names.json` has a `pantheon` part (Divinities and the Gate, Grand Temples, the 2 Wonders, the 3 Progress tokens, the Snake and Minerva; the Mythology and Offering tokens, which have no TTS name, by the hash of their face image). The Advisor fills it into the script (`@PANTHEON@`) when it sends it. The script reports a Divinity card's back (its Mythology, or the Gate's, or `temple` for a Grand Temple: the backs differ, so this is public) and names a Divinity in the **host's own hand** (the owner's draw or Divine Theater deck, marked `own`); nothing in another hand is named. `places.json`'s `pantheon` part: the 6 spaces (from the mod board's snap points), the Pantheon area, each player's Divinity board (activated Divinities), the Ra Wonder row, where tokens lie on structure cards, and Minerva's track. The live checks for these are Part D of `docs/tts-live-checks.md`.

The Advisor embeds these files. `tools/tts-check.cmd` reads the live table once and compares it with the practice fixture.

The Advisor follows the table with these files (ticket 33): with "Follow the TTS table" ticked in the Advisor Window it sends `snapshot.lua` about once a second, waits until the table is settled (nothing held or moving, the same snapshot twice in a row), and reconciles it with the Move Log (`engine/src/Advisor/Tts/Reconciler.cs`): one explaining chain of Moves and Reveals is entered, several are offered as choices, anything else is a Desync listed place by place. Coins, the Conflict Pawn and looting tokens are only notes. `7wd-advisor --tts-file F` follows a snapshot saved in a file instead of the live table.

Around that (ticket 34, `engine/src/Advisor/Tts/TableLifecycle.cs`): the owner's colour comes from the host's TTS seat ("You sit: Auto", overridable; asked when the host isn't at White or Red); a fresh setup on the table is offered as "New game detected" and never started by itself; a promo Wonder in the draft that the game was started without offers "Enable <promo> for this game"; and after a restart, following being switched on, a new game or TTS loading a game, the first readings use a deeper catch-up search until the table and the log match. Owner's live checks for tickets 32–34: `docs/tts-live-checks.md`.
